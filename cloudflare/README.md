# 共有URL版の保存基盤

2026-09-13：移行手順1。既存のGitHubリポジトリ・Pages・暗号化データ・同期処理を維持したまま追加。

- Worker: `janroku-api`
- D1: `janroku-shared`（作成リージョン APAC）
- 接続確認: `https://janroku-api.janroku-one.workers.dev/health`
- 設定: `wrangler.jsonc`、スキーマ: `migrations/0001_initial.sql`

現時点で公開しているのは読み取り専用の接続確認のみ。その他のURLは404、GET以外の接続確認は405。参加者データの取得・追加・更新API、共有キー発行、データ移行は未実装。

全データはgroup_idで分離する。対局JSONに元のルール・点数・収支を保持する。変更履歴とrevisionは次段階の競合検知・復元用。複合キーで他会の同一メンバーID・対局IDを区別する。共有キーはランダム生成した値のハッシュだけを保存する設計で、現在キー・グループ・実データは未登録。

次段階では、サーバーで認可したgroup_idだけをクエリへ渡し、変更・履歴・revision更新を同一トランザクションで確定する。スキーマだけではアクセス制御は成立しない。共有URL認証と保存APIを実装・検証した後に既存データを移行し、最後にフロントエンドの接続先を切り替える。

このWorkerはCloudflare APIから配置した。ソース変更時はこのディレクトリを対象にデプロイすること。現在のGitHub PagesワークフローはWorkerをデプロイしない。
