# 雀録ニュースの文案カタログ

日別画面の「ニュース」に接続しています。開催日当日から、1戦でも記録があればすぐ閲覧できます。対象日の記録の追加・訂正に合わせてブラウザ内で記事を更新し、何度でも閲覧できます。未来の日付のみ日本時間の開催日まで待機します。記事には固定の公開時刻ではなく、対象日の記録の最終入力・訂正日時を表示します。初回読み込みでは記事カタログを読み込まず、ニュース画面を開く際に読み込みます。
外部AIへのリクエストや個人データの保存は行いません。実名・合言葉・トークン・対局データはこのフォルダーに含めません。

## ファイルと件数

| ファイル | 件数 | 1件の単位 |
| --- | ---: | --- |
| [headlines.json](./headlines.json) | 30 | 一面見出し |
| [daily-news.json](./daily-news.json) | 30 | 本日のニュース1件 |
| [member-summaries.json](./member-summaries.json) | 100 | 編集部によるユーモアのある一言総評 |
| [fictional-interviews.json](./fictional-interviews.json) | 100 | 質問と架空回答のセット。質問と回答を別々には数えない |
| [article-paragraphs.json](./article-paragraphs.json) | 150 | 記事本文に使う段落。1件で約1,000文字の記事ではない |
| [fictional-reader-comments.json](./fictional-reader-comments.json) | 600 | 架空の読者コメント1件 |
| **合計** | **1,010** | 穴埋めする前の固有文案数 |

記事本文は従来100件に、勝ち越し・雪辱・継続した好成績・称号・記録上の初同卓を扱う文案を各10件追加し、計150件です。従来の集計文も、全戦で上位だった場合と勝敗が分かれた場合で自然に言い分けるよう修正しています。見出し15件、ニュース15件、総評50件、インタビュー50件、読者コメント300件も対戦テーマです。読者コメントは計600件を維持しています。
本文は `paragraphRole` が `lead`（導入）、`feature`（主役）、`detail`（詳細）、`spotlight`（脇役）、`closing`（締め）の5用途で、各30種類です。
名前・数字の置換結果を別テンプレートとして数えません。
速報専用カタログは今回の件数指定に含まれないため未作成です。

## データ形式

[template.schema.json](./template.schema.json) はJSON Schema、[fact-contract.json](./fact-contract.json) は穴埋め・判定に必要な集計値の定義です。
後者のフィールドはニュース用集計器 `src/domain/news/facts.ts` の契約です。既存の `PlayerStats` をそのまま使わず、対象日の保存収支と順位から計算します。

```json
{
  "id": "headline.narrow-leader.01",
  "event": "narrow-leader",
  "topic": "daily-lead",
  "priority": 85,
  "conditions": {
    "all": [
      { "fact": "player.isSoleDailyLeader", "op": "eq", "value": true },
      { "fact": "day.leadGap", "op": "gt", "value": 0 },
      { "fact": "day.leadGap", "op": "lte", "value": 5 }
    ]
  },
  "text": "首位と2位はわずか{day.leadGap}pt差！{player.name}が先頭を確保"
}
```

上は説明用の抜粋です。実ファイルには、実記録であることなどの共通条件、`requiredFacts`、`placeholders` も含まれます。

- `conditions.all`：すべて成立した場合だけ候補にする。1つでも不明・不成立なら使わない。
- `value`：定数との比較。`valueFact`：別の集計値との比較。どちらか片方のみを指定する。
- `eq / ne / gt / gte / lt / lte`：型をそろえて比較する。大小比較は数値のみ。文字列の数値・truthy判定は使用しない。
- `requiredFacts`：文章と条件が必要とする値。欠損・null・型違い・NaN・Infinity・空の表示名は不採用。0やfalseは欠損と区別する。
- `placeholders`：文章内の `{player.name}` などの一覧。表示時に値で置き換える。
- `event / topic`：出来事と重複回避用の話題。同じ出来事の言い換えを、別ニュースとして複数採用しない。
- `paragraphRole`：本文段落だけが持つ用途。導入から始め、複数の出来事を紹介して締めへつなぐための選択材料。
- `priority`：ニュース価値の初期目安。同条件内の文案の優劣ではない。複数人への話題配分も別途必要。
- `fictional / voice / displayLabel`：発言の扱いと表示名。インタビュー・読者コメントの架空表示を取り除かない。

置換時は、収支に正負の符号を付け、差・回復幅・回数・順位にはプラス符号を付けません。数値の `pt` は文案側に含まれるため、置換値に二重で付けないようにします。
`day.date` は対象日の年月日として表示します。比較は表示用文字列に変換する前の数値で行います。

## 条件の一覧

共通して、正しく復号できた実記録・同じ麻雀会のデータ・集計値検証済み・対象日への参加1戦以上が必須です。
合言葉不一致時の疑似表示を取材対象にしてはいけません。

| event | 主な使用条件 |
| --- | --- |
| daily-leader | 日次収支で単独首位、本人がプラス、当日参加者4人以上 |
| narrow-leader | プラスの単独首位、日次2位との差が0超〜5pt以下 |
| hundred-plus | 日次収支が100pt以上1,000pt未満。「3桁」は整数部分の桁数 |
| three-tops | 当日のトップ3回以上。連勝とは書かない |
| all-tops | 当日3戦以上、本人の全参加対局がトップ |
| no-last | 当日4戦以上、4位が0回。プラス収支や守備力は推定しない |
| all-top-two | 当日3戦以上、本人の全参加対局が2位以内 |
| second-specialist | 当日の2位3回以上、トップ0回。1位との点差は推定しない |
| back-to-positive | 順序確認済み、当日途中累計が−30pt以下、現在の合計がプラス |
| latest-turns-positive | 順序確認済み、2戦以上、本人の最新対局直前が0pt以下、最新対局がプラス、現在合計もプラス |
| latest-top | 順序確認済み、2戦以上、本人の最新対局が1位 |
| consecutive-tops | 順序確認済み、本人の当日最長連勝が2以上 |
| consecutive-top-two | 順序確認済み、本人の当日最長連対が3以上 |
| personal-daily-best | 比較履歴の取得完了、同条件の過去参加日3日以上、当日3戦以上、プラスかつ過去最高を厳密に上回る |
| small-positive | 日次収支が0超〜5pt以下 |
| small-negative | 日次収支が−5pt以上0未満 |
| recovery-still-negative | 順序確認済み、当日途中累計−30pt以下、底から20pt以上回復、現在合計はまだマイナス |
| one-game | 当日の本人参加対局がちょうど1戦 |
| zero-day | 当日2戦以上、収支の合計が正確に0pt |
| tough-day | 日次収支が−50pt以下。人物評価や原因の断定に使わない |
| nemesis-win / nemesis-loss | 開催前の相性が悪い・やや悪い相手に、当日の同卓順位で勝ち越し／負け越し |
| favorite-win / favorite-loss | 開催前の相性が良い・やや良い相手に、当日の同卓順位で勝ち越し／負け越し |
| rival-even | 開催前3戦以上で相性が普通、当日の上位回数も同数 |
| first-duel | 開催前の同卓記録なし、当日の順位比較で勝ち越し。実生活の初対面とは書かない |
| duel-win / duel-even | 当日同卓した相手への上位回数で勝ち越し／同数。対局トップ・直接の点棒移動とは別 |
| title-upset / title-defense | 開催日終了時点の称号が上位／下位の相手に、当日の同卓順位で勝ち越し |

相性は既存の `calculateCompatibility` と同じ「相手より上位だった回数÷同卓回数」で判定し、開催日前の記録だけを使います。これは文案の選択条件に使い、文章の中で判定ラベルを繰り返し説明しません。

称号は当日の成績も含めた開催日終了時点の同会全記録から、戦績画面と同じ計算で求めます。比較対象となる全員の母集団も同じ日付で区切ります。9月の記事に10月の対局を含めないため、後の成績で現在の称号が変わっても9月の記事は変わりません。当時の対局記録自体を訂正した場合は、その訂正を反映して再計算します。

## 集計時に守ること

1. **対戦日で絞る。** `Game.date` を使い、入力日・閲覧日と混同しない。「本日」「今日」は表示中の対象日を意味するため、必ず日付を同じ記事に表示する。
2. **当日集計を使う。** `PlayerGame.cumulativeResult` は通算値なので流用しない。本人の当日収支を開始0から積み上げ直す。
3. **保存済みの収支と順位を使う。** 収支直接入力を勝手に持ち点へ逆算しない。順位同点時は保存順位に従い、日次収支同点を席順などで単独首位に変えない。
4. **当日入力と後日入力を分ける。** ユーザーの運用に従い、本人の全参加対局が開催日当日（日本時間）に入力され、入力時刻に重複がなければ `createdAt` 順を実施順として扱う。後日入力、時差のない日時、同時刻で順序が不明な場合は、その本人の `orderVerified=false` とし、連勝・最新対局・回復系を使わない。収支・順位回数は引き続き使う。ID順で順序を補わない。
5. **開催終了を推測しない。** 対局追加のたびに記事は変わり得る。「最新の本人参加対局」と「開催の最終戦」は別。確定ボタンや当日の終了時刻を追加で要求しない。
6. **過去記録は未来を含めない。** 比較対象は選択日より前の本人の参加日だけ。対象日自身を最高値の比較元に含めない。記録が欠けている可能性があるなら記録更新記事は見送る。
7. **比較の条件をそろえる。** 自己ベストは、本人の各参加日における対局形式と全スコアルールの組み合わせ集合が一致する日だけを比較する。ウマ・オカ・原点・返し点・丸め・箱下・同点処理・点数単位などを含め、任意のルールIDだけでは一致としない。旧形式の省略値は既存スコア仕様の既定値に正規化する。不明なら比較しない。混在する場合は形式別対局数とルール構成を併記する。これは日次合計の自己記録であり、平均収支・同じ対局数・生涯自己ベストとは表現しない。
8. **精度をそろえる。** 記録の収支は0.1pt単位の整数として加算・比較する。表示前に丸めた値で0判定しない。0.1pt単位でない入力は黙って丸めず、集計値の検証で扱いを決める。
9. **派生値の整合性を検査する。** `topTwoCount=topCount+secondCount`、順位回数の合計が対局数と一致、各回数は対局数以下、`beforeLatestResult+latestResult=totalResult`、`recovery=totalResult-minCumulative`、連続回数は該当順位回数以下、単独首位と差は全参加者の収支から算出、などを確かめる。
10. **入力にない出来事を作らない。** 役・和了・放銃・オーラス・点棒移動・打牌・会場での発言・観客の反応・性格・仕事の評価は生成しない。調整済み記録を使う場合も、あくまで保存済み記録についての記事であると扱う。

## 文章を組み立てるとき

- 見出し・ニュース・本文は、使用条件、結果の重要度、直近10開催日の使用状況、決定的な巡回順の順で候補を選ぶ。同じ文章を避けるために重要度の低い対戦へ主役を変えない。
- 個人の見出しは、同条件の日次自己記録（過去3日以上・当日3戦以上）、3戦以上の全勝、大きな巻き返し、日次首位などの事実を中心にする。僅差首位は2位との差が5pt以内。入力時刻から対局順序を確認できない日は、逆転や連勝を推定しない。
- 対戦の見出しは **当日3戦以上・上位回数の差が2以上** を前提とし、(a) 勝ち越した側の過去同卓5戦以上・上位率30%以下という雪辱、または (b) 両者が日次収支で3位以内かつプラス・同卓4戦以上・上位回数の差3以上、に限定する。称号差だけでは格上撃破扱いにしない。
- 本文・ニュースで勝ち越しを取り上げる最低条件は **同卓3戦以上・上位回数の差2以上**。1対0、2対0、2対1は取り上げない。五分の対戦は、両者が日次収支で2位以内かつプラス、同卓6戦以上の場合のみ本文・ニュースの候補にする。見出しにはしない。
- 対戦の特集は本文で最大2組。同じ組を逆向きに再掲載しない。大見出しと導入の人物・対戦を一致させる。対象がなければ日次首位、各選手の順位内訳、収支の幅、記録更新などを中心に構成し、同卓していない選手を直接対決とは書かない。
- 上位回数は `pair.resultSummary` で自然に言い分ける。3対0なら「同卓した3戦すべてでA選手がB選手より上位」、3対1なら「同卓4戦のうち3戦でA選手がB選手より上位」。敗者の「上回ったのは0回」という列挙はしない。ここでの上位は二人の順位比較であり、卓全体のトップを意味しない。
- メンバーを麻雀選手として扱い、スポーツ紙の報道・選手寸評・試合後の架空取材の文体にする。表、スクロール、入力や保存など、このツールの操作を笑いの題材にしない。
- 記事本文は一日全体を扱うスポーツ記事として構成する。150件の対戦段落に加えて `src/domain/news/dayReport.ts` の条件付き文案から、主役の成果、上位争い、各選手の内訳、収支の振れ幅、巻き返し、自己記録、飛びを選ぶ。「相性が良い／悪い」などの判定説明を各段落に加えない。対戦段落で現在の称号を添えるものは最大1件。これとは別に、当日の称号変更を最大2人まで掲載する。
- 称号の昇降があった日は、その話題を通常の称号紹介より優先し、最大2人分を対戦段落に短く添える。開催日前と当日終了時の同会全成績で比較し、昇格と降格が両方あれば各1人、同方向だけなら変化の大きい順に取り上げる。初参加、称号の据え置き、過去記録が不正な場合は昇降を報じない。偏差値は周囲の成績にも影響されるため、勝ったから昇格／負けたから降格とは断定しない。追記20種類も過去10開催日の重複回避に含め、後日の成績では過去の追記を変えない。
- インタビュー・総評は対戦テーマを半分程度にし、選手と開催日をずらして交互に配分する。コメントは約20件のうち最大10件を対戦テーマにする。見出しとニュースには固定の対戦枠を設けない。条件に合う候補がなければ個人の成果を扱う。
- 通常は800〜1,200文字、8戦以上で材料が豊富な日は約1,500文字（上限1,550文字）を目安とする。1〜2戦の日は上限650文字、3戦の日は上限850文字とし、材料の少ない日は短くまとめる。段落を途中で切ったり、弱い対戦結果を加えて字数を稼いだりしない。
- 飛びは点数入力の確定した持ち点と、その対局に保存された `bustIncludesZero` で判定する。収支入力、持ち点なし、注記に逆算・推定・調整・仮入力・復元・換算がある対局は不明とする。飛ばした相手や放銃原因は推定しない。飛び後の収支は本人の全対局の順序が確認できる場合だけ掲載する。持ち点・入力モード・注記の訂正時も記事を再計算する。
- 特別なイベントに該当しない選手も、当日の全勝・複数勝利・2位回数・収支の正負に応じて `editorial.ts` の補完文案から選ぶ。文型は号内で消費し、全員に同じ総評やQ&Aを配らない。少数対局の全勝を長期的な強さの証拠とはしない。
- 負けの話題を同じ人について重ねない。特に総評、インタビュー、読者コメントで同じ人を繰り返しいじらない。
- インタビューは「その人を題材にした創作」として表示する。実際の発言の引用符、取材日時、実在の記者名、録音風の演出を付けない。
- インタビューで名前を出すときは必ず「さん」または「選手」を付ける。現在の対戦文案は「選手」で統一し、検証スクリプトと描画前の置換でも呼び捨てを防ぐ。
- 読者コメントに実在アカウント名や投稿時刻を付けない。Yahoo!ニュースの配信記事・実投稿として表示しない。
- ユーザー指定により、架空と明示した「いいね数」と返信を表示する。実投票や実投稿は受け付けない。いいね数は話題（苦手克服・称号差・接戦など）と文の具体性・応援表現による重みに、文章と麻雀会・開催日から決まる揺らぎを加えて算出する。
- 約20件の親コメントを維持し、反響の大きい約3分の1に、親と同じイベントを受ける返信を1〜3件付ける。同じ号で同じ返信文型を使い切ったときは無理に補充しない。返信も過去10開催日の文案選択に含め、再閲覧では同じ内容・いいね数を表示する。
- 読者コメントと返信は観戦者のくだけた口調にする。呼称は読者ごとに約8割が呼び捨て、約2割が「選手」で、開催日と読者キーから再現する。インタビューにはこの処理を適用せず、選手本人の回答では引き続き敬称を必須にする。
- 重複回避の参照範囲は、同じ会の対象日より前の直近10開催日。暦の10日前ではなく、実際に対局のある日を数える。対象日自身、未来の日、別会の記録を含めない。
- 過去に選ばれたテンプレートIDに加え、名前・日付・数値を正規化した本文と長めの文も照合する。総評・インタビューの補完候補や記事の比較段落、締め、読者コメントにも適用する。候補が残っていれば未使用を優先し、全候補を使用済みなら最後の使用が古いものを選ぶ。
- 古い開催日から記事を再現し、実際に採用した文案の使用履歴を10日分ずつ引き継ぐ。直近10日の各記事を履歴なしで個別生成する方式や、閲覧順に履歴を保存する方式は使わない。したがってスマホ・PCや閲覧順に依存せず、将来の開催日を追加しても過去記事は変わらない。
- 復号済みデータの生存期間に限り、ブラウザメモリで再現済み記事を再利用する。収支・順位・開催日・入力日時・ルール・名前などの訂正は内容から検出し、過去から再編集する。読めない過去日は文章を推測せず、空の履歴として10日枠に数える。
- 有限の文案を使うため、長期的な表現の再登場はある。リロードのたびにランダム化せず、一日の記事としての一貫性を優先する。実名入り文章を外部AIへ送信しない。
- 生成結果を保存する場合、実名を穴埋めした文章を公開JSONや公開コミットに追加しない。まずは復号後のブラウザ内だけで組み立てる。
- 置換は固定キーの文字列置換とし、`eval` やHTML実行を使わない。名前や文章はReactのテキストとして表示し、`dangerouslySetInnerHTML` に渡さない。
- ニュース画面の「この日の速報」は過去の結果のダイジェストとして表示する。初回は静止し、読者が再生を選ぶと切り替わる。リアルタイムの保存通知としては扱わない。削除・訂正・後日入力があれば記事全体を再計算する。

## 検査

リポジトリのルートで実行します。追加パッケージは不要です。

```sh
node scripts/validate-news-templates.mjs
```

1,010件の内訳、ID・同一ファイル内の全文重複、条件キー、型、穴埋め参照、必須値の欠損・null、不正な対象、イベントの境界を検査します。特集の選考基準と小標本・雪辱・上位対決の境界は `featurePolicy.test.ts` で検査します。
検査用データは架空の集計値で、実際の参加者データは使いません。この検査はカタログと条件の参照判定に限られます。実際の集計・日付の境界・再現性・画面の公開制御は `src/domain/news/news.test.ts` と `src/pages/DailyPage.test.tsx` で別途検査します。
