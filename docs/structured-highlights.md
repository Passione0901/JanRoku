# ハイライトの構造解析

更新日: 2026-09-15

ハイライト解析の改修内容と、2026-09-15に実施した検証結果です。

## 目的と対象

50文字までの対局メモから、人物と出来事を特定できる部分を抽出し、ニュースの材料にします。任意の日本語を理解することや、入力された出来事の真偽を証明することは目的に含めません。

対象の中心は和了・放銃・打点・順位の逆転・箱下です。聴牌、手作り、通常の牌のツモ、和了は別の状態として扱います。連荘、打ち筋、心理などを、和了や最終成績から補って記事にすることはありません。

外部LLM、外部AI API、外部の自然言語解析サービスにはメモを送信しません。解析はニュース生成時にブラウザ内で行い、入力中のキー操作ごとには実行しません。

## 処理の分離

| 段階 | 担当 | 出力 |
| --- | --- | --- |
| 語句抽出 | `highlightLexer.ts` | 原文上の位置を持つ語句と、複数の分割候補 |
| 構造化・意味検証 | `highlightAnalysis.ts` | 人物、動作、役、点数、状態、時間関係、判定理由を持つ出来事 |
| 表現への変換 | `highlights.ts` | 検証済みの出来事だけを記述したニュース用の短文 |
| 掲載箇所の選択 | `highlightEdition.ts` | 記事、見出し、総評、インタビュー、読者コメント等への反映 |

解析器は記事用の日本語を生成しません。ニュースの各欄も原文を個別に再解析しません。構造化した出来事を共通の材料とし、その情報だけで書けるテンプレートを選びます。

旧来の全文書き換え処理を、構造解析で拒否された文に対する救済処理として呼び出すことはありません。互換用の `parseHighlight` も、同じ構造解析から得た候補のうち最優先の1件を返します。複数件を使う処理は `parseHighlights` を使用します。

## 原文と位置情報

入力原文は変更せず、保存・表示に使用します。全角・半角の表記揺れなどを正規化するのは、解析用の文字列だけです。

原文の範囲はJavaScriptの文字列と同じ **UTF-16オフセット**で管理します。`start` は含む位置、`end` は含まない位置で、原文の `slice(start, end)` と対応します。

正規化では `Intl.Segmenter` で分けた書記素ごとにNFKCを適用し、正規化後のUTF-16単位から元の書記素の範囲を引ける対応表を作ります。半角の濁音、結合文字などでも、抽出した語句の根拠を原文へ戻せるようにします。略語から複数の意味を取り出す場合、複数の語句が同じ原文範囲を根拠に持つことがあります。

この位置の単位と、入力欄の50文字制限は別です。入力制限は既存どおりUnicodeコードポイントを数えます。UTF-16の長さをそのまま入力文字数には使用しません。

参加者の名前は麻雀用語の正規化より優先して保護します。対象はその半荘の参加者だけです。同名や名前の重なりで人物が確定できない場合は、似た名前へ補正して採用しません。

## 候補の探索

語句の抽出には麻雀用語の辞書と、動作・助詞・状態・時間・接続表現などの専用辞書を使います。個別の全文への一致だけで判定せず、語句の組み合わせから動作ごとの関係を作ります。

長い単語を優先的に探索しても、その分割へ即決しません。例えば「チートイツモ」のように役名と動作の境界に候補がある場合、複数の分割を残して意味の整合を調べます。

語句の経路候補には `HIGHLIGHT_PATH_LIMIT = 64` の上限があります。探索の途中や最終結果で上限による切り捨てが必要になった場合は、その事実を `truncated` として保持し、解析結果を記事に採用しません。上限を超えた候補から都合のよい1件だけを選んで公開しないためです。

人物や動作などの必須情報について、複数の有効な解釈が食い違う場合は曖昧として不採用にします。不明な任意情報は不明のまま保持します。未知の語句は明示的な未解決情報として残し、意味を変える可能性がある部分を無条件に削除しません。

## 人物・状態・時間の検証

人物は動作と助詞の関係から割り当てます。

| メモ | 和了者 | 放銃者 |
| --- | --- | --- |
| 山田が佐藤に倍満を放銃した | 佐藤 | 山田 |
| 佐藤が山田から倍満をロンした | 佐藤 | 山田 |
| 佐藤が山田に倍満をぶち当てた | 佐藤 | 山田 |

「親の山田が佐藤に満貫を放銃した」では、親の情報は山田へ割り当てます。佐藤の和了を親満に変えません。

主語の省略は、同じ人物の動作が続いていると判断できる場合に限って扱います。別の人物、未特定の人物、次局などが現れた場合、直前の人物をそのまま新しい出来事へ割り当てないことが重要です。

否定や推測は動作を見つけた時点ではなく、文末や後続の補足を含めて検証します。「役満ツモ、と思ったら違った」は役満和了として採用しません。「役満を狙ったが満貫をツモった」では、成立していない役満と成立した満貫を区別します。

途中のトップと最終的なトップ、途中の箱下と終了時の飛びも分けます。関連する和了と逆転・箱下を一つの説明にまとめる場合は、解析器が明示した出来事の関連IDを用います。同じ人物や同じ時間区分という理由だけでは統合しません。

## 点数の意味

点数には、和了の基本獲得点、ツモの支払額、持ち点、点差、複数局の累計などの区分を付けます。数字が出てきたというだけで、和了打点へ結び付けません。

半荘終了時の持ち点だけでは、途中の和了打点や途中の親子は検証できません。最終順位や終了時の箱下など、保存記録と比較できる情報だけを照合します。ハイライトを理由に、保存済みの点数や順位を変更することはありません。

採用優先度に使う基本獲得点は、確定値と比較用の下限を分けます。

| 情報 | 優先度に使う値 | 記事での点数の扱い |
| --- | --- | --- |
| 親の三倍満ツモ | 36,000点 | 確認済みの情報だけを使用 |
| 子の役満ツモ | 32,000点 | 確認済みの情報だけを使用 |
| 親子不明の役満ツモ | 下限32,000点 | 32,000点を実際の獲得点と断定しない |
| 打点不明の和了 | 不明 | 0点の和了と表示しない |

表示用候補では、並べ替えのために不明点数を0として扱う箇所があります。この値を本文の事実として出力しません。構造解析のデータでは不明値を `null` とし、確定値と区別します。

## 既存UI・保存・ニュースとの関係

この改修は解析処理とニュース反映の分担を変更するものです。ハイライトの入力位置、任意入力、IME対応、APIの文字数検証、原文の保存・編集・削除・同期・下書き・バックアップ・復元の契約は変更しません。既存データの移行やグループの統合も行いません。

解析結果は再利用し、原文・参加者・成績・ルール・辞書・解析器の版に依存するものとして扱います。これらの変更で古い結果が残らないことは、実装検証の対象です。

ニュースでは従来の掲載箇所制限、人物の偏り抑制、過去10開催日分の重複回避、当時の称号、架空インタビュー等の表示方針を維持します。独立した逆転には専用の文案を使い、和了があったとは補いません。適切な文案がない出来事は、その欄に掲載しません。

## 形態素解析ライブラリを追加していない理由

今回の構成では、人物と動作の対応、親子、否定、点数の意味などを麻雀専用の規則で管理しています。形態素解析で一般語や活用形を分けても、これらの意味検証は別途必要です。

そのため、まず専用解析の責務と誤採用を防ぐ検証を整え、汎用の形態素解析ライブラリは必須依存にしていません。これは、専用実装の方が高精度・高速だと比較実験で証明したという意味ではありません。

kuromoji.js、Linderaなどとの比較試作は実施していません。精度の改善効果、辞書を含む通信量、初期化時間、メモリ使用量、互換性、保守性やライセンスについて、比較実測済みとは扱いません。今後併用を判断する際は、同じ評価用メモを使って差を測る必要があります。

## 評価方法と限界

過去に提示された102文はAI生成の既知の例文です。すでに実装調整で確認しているため、未知の入力に対する精度の証拠にはせず、回帰テストに使います。

評価では検出件数だけでなく、和了者・放銃者・動作・打点・親子・状態などの期待値を確認します。語順や否定を変えることで意味が変わる対照例も用います。

| 区分 | 意味 |
| --- | --- |
| 正しく抽出 | 記事に使える事実を、人物や意味を取り違えずに抽出した |
| 意図どおり不採用 | 推測、否定、未成立、人物不明などを方針どおり拒否した |
| 未対応 | 採用可能な明確な事実があるが、現在の解析で取り出せなかった |
| 誤抽出 | 誤った人物・出来事・点数・状態などを採用した |

実装調整に使用していない実際の対局メモによる独立評価は、まだ実施していません。新たに作成した人工的な安全性テストも、未知の実際のメモに対する性能を保証するものではありません。

構造解析で読めたことと、記事への掲載は別です。候補の優先度、掲載数、人物の偏り、文案の条件によって、解析成功した出来事でも掲載されない場合があります。
